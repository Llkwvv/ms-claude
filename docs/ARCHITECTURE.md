# 架构设计文档

## 概述

ModelScope Claude Code Proxy 是一个轻量级模型代理系统，用于自动切换和调度多个模型，实现智能的模型选择和失败恢复。

## 系统架构

```
┌─────────────────────────────────────────────────────────┐
│                    Claude Code                           │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│               Model Proxy（代理层）                        │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐      │
│  │ 模型列表管理 │  │ 优先级调度  │  │ 失败记录    │      │
│  │ 每日自动更新 │  │ 额度感知切换 │  │ 规则优化    │      │
│  └─────────────┘  └─────────────┘  └─────────────┘      │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│                    ModelScope API                        │
│   Qwen │ DeepSeek │ Yi │ ... (50+ 模型)                  │
└─────────────────────────────────────────────────────────┘
```

## 核心组件

### 1. Model Proxy（主代理类）

**文件**: `src/core/proxy.py`

**职责**:
- 协调各个模块工作
- 处理请求转发和模型切换
- 实现额度感知和自动切换
- 管理失败重试逻辑

**主要方法**:
- `request()`: 处理请求（支持流式/非流式）
- `get_available_model()`: 获取可用模型
- `get_status()`: 获取代理状态

### 2. Priority Scheduler（优先级调度器）

**文件**: `src/core/scheduler.py`

**职责**:
- 按优先级选择最优模型
- 实现冷却时间机制
- 处理模型状态转换
- 生成健康报告

**特性**:
- 指数退避重试
- 响应时间统计
- 失败率监控

### 3. Model Manager（模型列表管理）

**文件**: `src/models/manager.py`

**职责**:
- 加载和管理模型列表
- 从ModelScope API更新模型
- 维护模型缓存
- 按优先级过滤模型

**功能**:
- 本地缓存（JSON）
- 自动更新检查
- 模型状态管理
- 统计信息收集

### 4. Failure Tracker（失败记录服务）

**文件**: `src/services/failure.py`

**职责**:
- 记录模型失败情况
- 分析失败模式
- 生成优化建议
- 导出统计信息

**特性**:
- 错误类型分类
- 时间窗口统计
- 失败阈值检查
- 日志持久化

### 5. ModelScope Service（ModelScope API服务）

**文件**: `src/services/modelscope.py`

**职责**:
- 与ModelScope API交互
- 获取模型列表
- 搜索和过滤模型
- 健康检查

## 数据流

### 请求处理流程

```
1. 用户发送请求
   │
2. ModelProxy.request()
   │
3. 获取可用模型 ← ModelManager
   │
4. 检查模型状态
   ├─ 可用 → 发送请求
   ├─ 配额不足 → 切换下一个模型
   └─ 失败 → 记录并切换
   │
5. 执行API调用
   │
6. 检查响应
   ├─ 成功 → 返回结果
   └─ 失败 → 记录错误，重试
   │
7. 更新统计信息
```

### 模型更新流程

```
1. 检查缓存时间
   │
2. 是否过期?
   ├─ 是 → 调用ModelScope API
   │        │
   │        ├─ 成功 → 更新缓存
   │        └─ 失败 → 使用旧缓存
   │
   └─ 否 → 使用缓存数据
   │
3. 应用优先级配置
```

## 错误处理

### 错误类型分类

| 类型 | 描述 | 处理策略 |
|------|------|----------|
| quota | 额度不足 | 切换模型，标记状态 |
| rate_limit | 限频 | 冷却后重试 |
| timeout | 超时 | 增加超时时间 |
| connection | 连接错误 | 重试，检查网络 |
| server | 服务器错误 | 重试，指数退避 |
| parsing | 解析错误 | 记录日志，不重试 |

### 重试策略

```python
max_retries = 3
retry_delay = 1  # 秒

# 指数退避
cooldown = base_cooldown * (2 ** failure_count)
```

## 配置说明

### 主要配置项

```yaml
model_priority:           # 模型优先级列表
modelscope:               # ModelScope API配置
  api_base:               # API基础URL
  cache_ttl:              # 缓存时间（秒）
quota:                    # 额度配置
  error_codes:            # 额度错误码
  max_retries:            # 最大重试次数
failure_tracking:        # 失败跟踪
  enabled:                # 是否启用
  failure_threshold:      # 失败阈值
streaming:                # 流式配置
  enabled:                # 是否启用
```

## 性能优化

### 缓存策略

1. **模型列表缓存**: 24小时TTL
2. **失败记录缓存**: 内存中保留最近1000条
3. **模型统计缓存**: 实时更新

### 并发控制

- 线程安全的模型管理
- 细粒度的锁控制
- 最小化锁持有时间

## 扩展性

### 添加新模型源

1. 实现新的API客户端
2. 继承`BaseModelService`
3. 注册到服务管理器

### 自定义调度策略

1. 实现新的调度器
2. 继承`BaseScheduler`
3. 配置中使用新调度器

## 故障排除

### 常见问题

1. **模型列表不更新**
   - 检查网络连接
   - 验证API密钥
   - 查看日志错误信息

2. **请求频繁失败**
   - 检查额度状态
   - 查看失败模式
   - 调整重试策略

3. **性能下降**
   - 检查缓存命中率
   - 分析响应时间
   - 优化查询逻辑
